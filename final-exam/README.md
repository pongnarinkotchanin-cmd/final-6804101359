# Software Testing with Playwright

Playwright Test project for the six SauceDemo final-exam scenarios.

## Requirements

- Node.js and npm
- Chromium browser installed by Playwright
- Network access to `https://www.saucedemo.com/`

## Run

```powershell
npm install
npx playwright install chromium
npx playwright test
npx playwright show-report
```

The test run writes the interactive HTML report to `playwright-report/` and the JSON report to `reports/results.json`. The run is configured with one worker, no retries, and retains failure evidence.

## Test cases

- `UT-01`: three independent login-validation cases
- `UT-02`: product Add to cart / Remove state and cart badge
- `IT-01`: real SauceDemo login followed by a browser-level inventory stub created with `page.setContent()`
- `IT-02`: a driver adds the requested `session-username` cookie and opens the real inventory and cart directly
- `ST-01`: complete purchase flow for Backpack and Bike Light
- `ST-02`: checkout required-field validation and recovery through order completion

## Integration test boundaries

In IT-01, authentication is real: the test visits SauceDemo and submits the standard login form. Only the inventory DOM is a stub; `page.setContent()` replaces the browser document with the two mock products. It does not replace or mock an internal SauceDemo module.

In IT-02, the driver is the test helper that prepares the browser context by adding the `session-username` cookie and navigating directly to `/inventory.html`, without using the login form. The inventory, add-to-cart behavior, and shopping cart are the real SauceDemo UI. Whether this cookie is sufficient for the current SauceDemo implementation is verified by the test assertions and report, not assumed.

## Reports

Reports are generated by Playwright from actual test runs. `reports/test-summary.md` records the observed result and failure details; it must be updated after each submitted run rather than manually changing Playwright's report files.
